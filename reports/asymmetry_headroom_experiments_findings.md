# Headroom experiments: where does evolving skills/prompts improve a capable agent?

Status: DRAFT for owner review (local). Prompted by a challenge to the README's "no measurable behavior change in either direction" framing — which was over-claimed and is now reframed. These two experiments locate, on **capable agents**, where evolution pays off and where it doesn't.

## Stage A — non-inferable convention (capable agent: Sonnet)
`evolve_prompt_section --target claude` on `claude_conventions.jsonl`, seed 0 (train on a headroom task `conv-run`, hold out headroom task `conv-test`), a **reasonable-but-incomplete** baseline ("prefer the repo's `bin/` wrappers" — *without* naming `bin/check`/`bin/run`), judge-free executable oracle, `--compile-floor`.

- **Result:** the behavioral pre-flight (`decision_signal: closed_loop`) found the **reasonable baseline already at `no_headroom`** (holdout 1.000). Told merely "prefer `bin/` wrappers," a capable agent discovers and uses `bin/check` on its own.
- **Interpretation:** text *does* move the agent — the banked **null→1.0** convention lift is real (`probe.json`, n=10) — but a *reasonable* instruction already saturates a capable agent, so evolution adds nothing over it. The value is **installing the missing signal** (null→instruction), captured by a reasonable baseline or a flat compiled template — **not** "evolution beats a good baseline."
- **Caveat:** 2-task holdout, low reps; the pre-flight aborted before the full gate. The behavioral baseline=1.0 on `conv-test` should be confirmed at higher reps. (`--force-saturation-check` would proceed but is expected to show baseline≈evolved.)

## Stage B — reasoning / process quality, the *strong* claim (capable agent: Sonnet)
Fair **process-shaped** substrate (8 hard-debugging tasks): a buggy `solution.py` + a **symptom** (one failing example) + a **hidden, held-out grader** that tests *different input classes* than the symptom — so a fix that overfits the reported case fails. This is precisely the "fix the class, not the example" discipline a GOLD methodology skill teaches. GOLD vs WEAK skills with byte-identical frontmatter; judge-free graders; the zero-LM constraint floor is **inert** here (so any gain is reasoning, not a restated convention). Anti-rigging prerequisite built: the sensitivity canary now uses a **per-task rule** (`n_beyond ≥ half the band`) — a single strong task can no longer carry a pooled mean.

- **Gate-A (Sonnet, reps 5, $2.75):** **all 8 tasks rate = 1.00** (40/40 runs pass the hidden held-out grader, including the 3 "hard" tasks). **Headroom band: 0/8 = NONE → KILL.**
- **Interpretation:** a capable agent **aces** the fair process-shaped substrate unaided — it already fixes the class, not the example. There is **no reasoning/process headroom for a methodology skill to fill**, so the strong claim ("evolution improves a *good* baseline on open-ended reasoning/quality, on a capable agent") is **closed by measurement** here. Reproduces the prior empty bands (Opus + Sonnet) with fresh per-task data.
- **Scope / honesty:** one substrate (algorithmic debugging) + Sonnet (the prior Opus band was also empty). This does **not** prove no process-headroom exists in *any* domain; it proves a fair, well-designed process substrate yields no band on a capable agent. Constructing ever-harder substrates until one bands would be substrate-fishing (the rigor violation we explicitly guard against). Combined with the three prior confirmed-negative neighbors, the weight of evidence is strong.

## Stage B-2 — spec-compliance conjunction (the band from *below*, capable agent: Sonnet)
A genuinely different domain (not algorithmic debugging): 6 spec-compliance tasks (slugify, normalize_path, format_duration, render_template, compare_semver, word_count), each requiring the **conjunction of ~13 independent, individually-easy requirements** — designed so that if the agent gets each ~95% right, the conjunction lands ~0.5 (squarely in the band). Fairness verified (symptom under-determines the spec; hidden held-out grader on disjoint inputs; good-faith-but-incomplete solutions also fail; generic skills reused unchanged; floor inert). Anti-rigging prereq built: the sensitivity canary now uses a **per-task rule** (`n_beyond ≥ half band`), not a riggable pooled mean.

- **Gate-A (Sonnet, reps 5, $2.20): all 6 tasks rate = 0.00** (30/30 runs fail the held-out grader). **Band 0/6 = NONE → KILL.** Sonnet writes a good-faith-but-incomplete solution every time, missing ≥1 of the ~13 conjoined requirements.
- **Interpretation:** the conjunction is too wide — Sonnet *fails uniformly* (below the band), the mirror image of Stage B's *acing* (above the band). Together the two genuinely-different substrates **bracket the 0.20–0.70 headroom band from both sides — the binary cliff.** The canary (does a methodology skill *lift* a capable agent in the band?) could not run, because no fair baseline landed in the band.

## Synthesis — the three-region map
Evolving skills/prompts improves a capable agent in **exactly one of three regimes**, and the campaign now locates all three:

1. **GREEN — non-inferable signal.** Where the text supplies something the agent can't infer from the task (an operating convention, a project wrapper, missing context), evolution + the gate deliver. Stage A: a `CLAUDE.md` region 0→100% held-out (n=10); a vague seed evolved 0.625→1.0 on unseen wrappers. Durable value: **install the missing signal + the gate certifies it didn't regress.**
2. **NULL — binary-correctness reasoning (the cliff).** Where a task is pass/fail and the agent is already competent, there's no room. Stage B + B-2 **bracket the band from both sides** on capable Sonnet — aced algorithmic debugging (1.00) and uniformly failed a 13-requirement conjunction (0.00), never landing in 0.20–0.70. A methodology skill has nothing to take hold of. ("Routes past the text" is a *tool-selection* fact, not a skills/prompts one.)
3. **FRONTIER — open-ended generative quality (untested).** Every experiment above used a *pass/fail* metric, which forces the cliff. The regime where "a better prompt yields better output" is most plausible — open-ended writing / analysis / design / review — is **unresolved**, because the only metric for it (an LLM judge) **saturates** and can't see the gradient even if it's there. Testing it needs a *trustworthy continuous-quality metric* (e.g. Weaver-style ensembles of independent cheap checks calibrated on a small labeled seed) — the active frontier.

This **refutes** the old "no change in either direction" framing (text demonstrably moves a capable agent in regime 1), honestly **bounds** the strong claim (regime 2 is a measured cliff), and keeps the promise **alive and falsifiable** (regime 3 is the open question, not a concession). Evolution earns no magic on its own — on our corpus GEPA is matched by best-of-N resampling — so the value is the **signal + the gate**, not the search. The honest product: *improve where there's a non-inferable signal, refuse where the agent's already competent, investigate the quality frontier, and tell you which regime you're in.*
