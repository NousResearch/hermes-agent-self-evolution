# 交付质量门 v2.0

## 六步流程（不可跳过）

### 1. 学习
- 搜全网最佳实践、专家教程、同类案例
- 查官方文档、GitHub issues、社区经验
- 找工具的正确用法（验证过的，不是猜测）

### 2. 使用
- 用学到的正确方法执行
- 能借助外部工具/软件的，不自己硬写
- 能委托子代理/多任务并行的，不串行

### 3. 经验攻略
- 遇到报错→搜 GitHub/StackOverflow/官方论坛
- 找到已知的坑和解决方案
- 记录失败路径，写入 skill 避免下次踩

### 4. 完善修改
- 产出后自我审查
- 对比专业标准：设计看 Behance 首页，代码看 GitHub 高星，策划看古田路9号
- 不满意就迭代，不交付半成品

### 5. 自我评定
- 对照用户需求逐条检查
- 对照专业标准打分（1-10分）
- **低于 7 分不发**

### 6. 最终交付
- 确认达标后才发给用户
- 附带：做了什么、怎么做的、自评分数
- 不达标→坦诚告知原因 + 补足计划

## 门禁规则
- 跳过任一步骤 = 违规
- 工具受阻→告知用户需要什么帮助
- 能力不足→诚实说明，推荐外部方案
- 同一个错误不犯第三次
